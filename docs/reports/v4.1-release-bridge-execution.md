## 5. Deploy do Agent — RESOLVIDO (2026-09-17, segunda rodada)

**Histórico:** o primeiro attempt foi bloqueado pela Cloudflare (code 10064): a nova versão não exporta `WorkspaceAgent`, classe DO ainda referenciada pelo deployment vigente (pré-V4). O deploy foi então **bloqueado como gate de preservação de dados** — o runbook `docs/ops/agent-history-migration-runbook.md` registra que o histórico legado nunca foi migrado e a deleção da classe destruiria o storage.

**Resolução:** o owner confirmou nesta sessão que **os dados do WorkspaceAgent são apenas de teste** ("os dados que temos são apenas para teste"), autorizando o deploy. Gate de preservação levantado.

**Executado:**
1. `apps/agent/wrangler.jsonc`: migration `{"tag":"v3","deleted_classes":["WorkspaceAgent"]}` (commit `234bf42`) — caminho sancionado pela plataforma, coerente com ADR-016 (migrations v1/v2 preservadas como histórico).
2. Deploy: `wrangler deploy --var BUILD_SHA/BUILD_ID/BUILD_TIME` → versão **`aea3c6f4-4593-434d-9e35-6837e2f5dd7e`**.
3. Smoke: `/health` = `status:ready, schemaVersion:5, buildSha` == HEAD (`234bf42…`), `buildId=v4.1-hardening`; `/health/agent` 200; API `/health` 200.

**Impacto permanente:** o storage SQLite do `WorkspaceAgent` (dados de teste) foi descartado pela migração. Não há rollback para a classe sem recriá-la (novos `new_sqlite_classes`); rollback do Worker segue possível via `wrangler rollback 78c57fb9-…` apenas para código pré-V4, que recriaria a classe sob demanda.

## 9. Deploy da API por digest (REL-02, V4.1 closure)

A partir desta mudança, todo push em `main` publica a imagem da API no GHCR com tag imutável por SHA e registra o digest.

- **Imagem:** `ghcr.io/kusts/meu-ted-api:sha-<gitSha>` (job `api-image` do CI, somente em push para `main`, com os mesmos `BUILD_SHA/BUILD_ID/BUILD_TIME` do job `docker`).
- **Como obter o digest:** no run do CI do commit, baixar os artefatos `api-image-provenance-<sha>` (arquivo `api-image-provenance.json` com `image`, `tag` e `digest`) ou `release-manifest-<sha>` (consolidado dos três apps em `release-manifest-<sha>.json`).
- **Deploy manual na VPS pelo digest** (sem automação — credencial da VPS nunca entra no CI):

```
DIGEST="<digest do artefato>"
docker pull "ghcr.io/kusts/meu-ted-api@$DIGEST"
docker tag "ghcr.io/kusts/meu-ted-api@$DIGEST" pi-finance-api:main
docker compose up -d
```

- **Verificação:** `curl -fsS https://api.synkroo.com.br/health` deve retornar `gitSha` igual ao SHA do commit deployado; `/ready` deve responder 200.
- **Rollback:** repetir os passos acima com o digest do artefato do commit anterior estável.
