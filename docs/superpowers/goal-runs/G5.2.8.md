# Goal run — G5.2.8

**Goal ID:** G5.2.8
**Status:** ready for auditor

## Contract

- **Objective:** aplicar budget de tokens, rate limit e redação de transcript sem dados sensíveis.
- **Acceptance:** chat possui limite diário de tokens por actor, limite de requisições por janela por actor, e nenhum segredo conhecido é persistido no transcript/actions/events/turn output.

## Implementation

- `apps/agent/src/schema.ts` version 4 cria `daily_token_usage`, `agent_rate_limits` e o marcador de backfill `transcript_redaction` no SQLite do Durable Object.
- `apps/agent/src/index.ts` aplica budget diário configurável (`AGENT_DAILY_TOKEN_BUDGET`, default 10.000), rate limit configurável (`AGENT_RATE_LIMIT_MAX_REQUESTS`, default 20/min/actor), e retorna 429 antes de enfileirar quando excedido.
- Budget conta input no enqueue e output no processamento; retry não re-reserva input porque o uso diário é persistido por actor/dia.
- `apps/agent/src/transcript-safety.ts` redige password/passcode/token/secret/api-key/authorization/cookie/client-secret, Bearer tokens e JWTs.
- Conteúdo redigido é usado em `messages`, `agent_actions`, `turn_queue.input_json`, `turn_queue.output_json` e eventos/response de assistant; o token delegado continua side-channel e nunca entra no transcript.
- `apps/agent/migrations/0003_safety_limits.sql` e `0004_transcript_redaction.sql`, `.dev.vars.example` e `worker-configuration.d.ts` documentam/persistem o contrato.
