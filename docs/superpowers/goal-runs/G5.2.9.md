# G5.2.9 — Retenção, export/delete, access log e minimização

## Objetivo

Implementar retenção de 180 dias, exportação/exclusão do histórico do Agent, logs de acesso auditáveis e payloads de action minimizados.

## Decisões

- O workspace Agent Durable Object continua sendo a fronteira do transcript.
- Membros exportam/excluem apenas o próprio histórico.
- Owners consultam o access log completo; membros consultam seus próprios eventos.
- Access log é append-only e não contém conteúdo de mensagem, tool payload ou credenciais.
- Sem commit ou deploy.

## Implementação

- `apps/agent/src/schema.ts`: schema v5 com `access_log` e índices.
- `apps/agent/migrations/0005_privacy_controls.sql`: migration correspondente.
- `apps/agent/src/index.ts`:
  - purge recorrente no alarm, inclusive workspace inativo, para registros com mais de 180 dias;
  - preserva turns `queued`/`running`;
  - delete usa `BEGIN`/`COMMIT`/`ROLLBACK`, incluindo o access-log mínimo na mesma transação;
  - `GET /history/export` com escopo derivado de `turn_queue.actor_id`;
  - `DELETE /history` idempotente, removendo o grafo do actor;
  - `GET /history/access-log` com escopo member/owner;
  - actions persistem somente metadados, sem duplicar conteúdo.
- Worker encaminha `/history`, `/history/export` e `/history/access-log` após autenticação de membership.
- PWA adiciona exportação JSON por download e exclusão com confirmação.
